# Архитектура AETHER MAIL (текущее ядро)

## Обзор

Почтовый стек на одном VPS в Docker Compose. Три сервиса, один внешний периметр nginx, сертификаты Let's Encrypt.

```
                 Интернет
        ┌──────────┴───────────┐
        │  nginx (edge/nginx)  │  :80 → редирект, :443 → HTTPS
        └──────────┬───────────┘
                   │ proxy_pass (внутренняя сеть)
        ┌──────────┴───────────┐
        │  panel (edge/panel)  │  FastAPI, не публикует порты наружу
        │  docker.sock (rw)    │  → управление ящиками через `setup` почтового контейнера
        └──────────┬───────────┘
                   │ SMTP :587 (внутренняя сеть)
        ┌──────────┴───────────┐
        │ mailserver           │  Postfix + Dovecot + OpenDKIM + OpenDMARC + Fail2ban
        │ :25 :465 :587        │  2525–2527 проброшены на 587
        │ :2525-2527           │
        └──────────────────────┘
```

## Потоки

**Управление ящиками.** Панель → `docker exec mailserver setup email …` через соккет. Аутентификация в панели: PBKDF2-HMAC-SHA256 (200k итераций), сессия — HMAC-подписанный токен, CSRF-токен на каждой форме.

**Отправка письма из панели.** Панель → `SMTP(mailserver:587)` → STARTTLS → авторизация ящиком (его реальным паролем) → Postfix → доставка. Панель не хранит пароли ящиков.

**Приём почты.** Внешний SMTP → :25 → OpenDKIM/OpenDMARC проверки → Dovecot (Maildir) → хранилище `./data/mail`.

**SSL.** certbot standalone на этапе установки, сертификат покрывает `mail.<домен>` и `<поддомен>.<домен>`, автообновление через `/etc/cron.daily/mail-cert-renew` с перезапуском контейнеров.

## Границы доверия

- Наружу открыты только: 25, 465, 587, 2525–2527 (почта), 80, 443 (панель).
- Порт панели (8080) наружу не публикуется — только через nginx.
- `./config` содержит приватные ключи DKIM — монтируется read-only в панель, исключён из git.
- Соккет Docker в панели — осознанный компромисс: даёт панели root-эквивалент на хосте. См. «Известные ограничения» в SECURITY.md.

## Что будет дальше (по спецификации §1, §12)

- `services/api` (Go) — управление аккаунтами, сессии, квоты, аудит.
- `frontend` (Next.js) — веб-клиент почты и админка.
- `services/mime-worker` (Rust) — безопасная разборка MIME и проверка вложений.
- Stalwart Mail Server вместо docker-mailserver (SMTP/IMAP/JMAP), PostgreSQL для метаданных, S3 для вложений.
